# Конфигуратор

«Конфиг для конфигов»: программа строит окно настроек прямо по комментариям в конфигах и
правит в файле только нужное значение. Сейчас здесь **кликабельный HTML-прототип** — проверяем
интерфейс, прежде чем писать саму программу.

## Как запустить

**Как программу** (настоящая тема, обновление, запись настроек HyprPanel):

```bash
sudo pacman -S --needed webkit2gtk-4.1          # окно на GTK + WebKit
~/mors-dots/configurator/app/mors-settings      # или шестерёнка в панели управления HyprPanel
```

**Как прототип в браузере** — только посмотреть интерфейс, команды не выполняются:

```bash
xdg-open ~/mors-dots/configurator/prototype/configurator.html
```

## Шестерёнка в HyprPanel

Кнопка 󰒓 в панели управления (аватарка слева вверху) зашита в код HyprPanel и открывает
его окно настроек. Код не трогаем: `app/gear-redirect.py` слушает события Hyprland и, как
только появляется окно `hyprpanel-settings`, закрывает его и открывает `mors-settings`.
Запускается из `config/hypr/lua/autostart.lua`. Родное окно HyprPanel можно открыть
кнопкой на странице «Система».

## Что уже есть в прототипе

- **Разметка в комментариях.** Над параметром пишется строка `#@name: … | type: … | range: …`,
  по ней рисуется переключатель, ползунок, пипетка, список или захват клавиш. Разделы — `#@section`.
- **Начало разбора.** Весь файл, после строки-маркера или только между двумя маркерами —
  чтобы не трогать то, что генерирует тема или другой софт.
- **Hyprland на Lua — настоящие файлы.** Окно читает `~/.config/hypr/hyprland.lua` и всё, что
  подключено через `require(...)`, правит значение под строкой `--@` прямо в файле и делает
  `hyprctl reload`. Значения-выражения (`t.border` и т.п. из темы rice) — только для чтения.
  Перед первой правкой файла за сеанс — копия в `~/.cache/mors-settings/backups/`.
  Разметка уже есть в `appearance.lua`, `input.lua`, `gestures.lua`; добавить в другой файл —
  вкладка «Править разметку».
- **Всё — настоящие файлы.** В окне программы Hyprland, kitty, HyprPanel и всё, что добавлено
  кнопкой «＋ Добавить конфиг», читается с диска и пишется обратно (копия перед первой правкой —
  в `~/.cache/mors-settings/backups/`). Свои конфиги запоминаются в
  `~/.config/mors-settings/settings.json`; для каждого можно задать команду, чтобы программа
  перечитала конфиг (`makoctl reload`, `pkill -USR1 -x kitty`…). Писать можно только в
  `~/.config`, `~/.local/share` и mors-dots. Демо-данные — только в браузере.
- **Шрифты и файлы — выбором, а не вводом.** Шрифт выбирается из списка установленных (`fc-list`)
  с поиском и превью, как в родном окне HyprPanel (пишутся name/label/style). У путей к файлам,
  картинкам и папкам — кнопка «Выбрать…» с окном выбора файлов KDE (`kdialog`; без него —
  системный диалог GTK/портала). В разметке: `type: font`, `type: file`, `type: image`, `type: dir`.
  Условия для путей:
  - `filter: *.png *.jpg` — в окне выбора видны только такие файлы;
  - `type: dir | glob: *.png, *.jpg, *` — выбирается папка, а в конфиг пишется `папка/*.png`
    (первая маска — по умолчанию, остальные — списком рядом с полем). Под полем видно, сколько
    файлов подходит, или предупреждение, если ни одного. Так сделан логотип fastfetch: он сам
    берёт случайную картинку из подходящих.
  Путь в домашней папке пишется как `~/…`, если так было записано в конфиге.
  В обоях — «＋ Добавить картинки…»: выбранные копируются в папку темы.
- **fastfetch (JSONC).** Разметка `//@` в `config/fastfetch/config.jsonc`: логотип, разделитель,
  а каждый модуль — переключатель `type: block`. Выключить модуль = закомментировать его блок `{…}`
  (`// ` ставится на отступ блока, как руками), включить — раскомментировать. Подходит и для
  других JSON-конфигов (waybar): формат «JSON / JSONC» в «＋ Добавить конфиг».
- **Свои форматы — прямо в программе.** Страница «Форматы»: встроенные форматы
  (`conf`, `space`, `ini`, `lua`, `jsonc`) описаны данными, а не кодом, их можно посмотреть и скопировать.
  Свой формат задаётся полями: комментарий; строка «ключ — значение» — регулярное выражение из пяти
  групп (отступ, ключ, разделитель, значение, хвост) или своя функция на JavaScript для совсем
  нестандартных строк; кавычки (`auto` / `json` / не трогать); вложенность (блоки со строкой входа и
  выхода, `[секции]`, скобки как в JSON); склейка пути ключа; подключение других файлов и шаблон этой
  строки; проверка перед записью — `json` или команда с `{file}` (например
  `hyprland --verify-config -c {file}`): если она вернула ошибку, файл не пишется. Под формой — проверка
  на примере: что программа поймёт в каждой строке и не изменит ли запись строку. Если части строки
  не склеиваются обратно ровно в неё, программа такую строку не трогает. Свои форматы хранятся в
  `~/.config/mors-settings/settings.json` и появляются в списке «Формат строк» у конфигов.
- **Конфиг из нескольких файлов.** Подключения (`source =`, `include`, `require`) становятся
  разделами; файл можно добавить вручную. Конфликты биндов ищутся по всем файлам.
- **HyprPanel на русском.** Полная копия его окна настроек: 871 настройка, 26 страниц,
  перевод всех строк. Код HyprPanel не меняется — правится только `config.json`.
  Цвета, которые перезаписывает `rice.py`, помечены «тема».
- **Система.** Тема всего райса (то же, что `rice.py apply`), масштаб интерфейса,
  кнопка «Обновить райс с GitHub»: `git pull --ff-only` → `rice.py apply <текущая>` →
  `hyprctl reload`; если изменились пакеты или установщик — предложит запустить `install.sh`.
- **Обои.** Превью всех картинок из папки текущей темы (`rice/wallpapers/<тема>/`),
  клик — поставить, кнопка — открыть папку. Пути никуда прописывать не нужно.
- **Мониторы.** Схема как в KDE: мониторы перетаскиваются мышью (прилипают к краям соседей),
  разрешение и частота — из того, что монитор реально поддерживает (`hyprctl monitors all -j`),
  масштаб, поворот, у монитора с прогревом — частота при старте и после прогрева. Применяется
  сразу через `hyprctl eval` (без перечитывания конфига — прогрев не сбивается), через 15 с без
  «Оставить» возвращается. Сохраняется в таблицу `MON` (`--@monitors`) в `hosts/<машина>/hypr.lua`.
- **Обои по мониторам.** Схема мониторов как в настройках экранов: выбери монитор — и картинка
  встанет только на него. Кадр подгоняется мышью (рамка в пропорциях монитора, колесо — масштаб),
  rice.py вырезает его ровно под разрешение монитора. Мониторы узнаются по EDID-описанию, разъём
  не важен. Картинку можно повернуть на 90° и отразить. Хранится в `rice/monitor-wallpapers.json`
  (у каждой машины свой, не в git).
- **Цвета из темы rice.** Программа красится в текущую тему (`rice/current` →
  `rice/themes/<тема>.json`) и перекрашивается сама при смене темы. В прототипе смену
  имитируют карточки тем на странице «Система»; при этом пересчитываются и цвета HyprPanel —
  так же, как в `rice.py`. В программе окно следит за `rice/current` и `config.json` само.

## Структура

```
configurator/
├── app/
│   ├── mors-settings           окно GTK + WebKit: интерфейс + мост к rice.py, git, config.json
│   └── gear-redirect.py        шестерёнка HyprPanel → mors-settings
├── prototype/
│   ├── configurator.src.html   исходник интерфейса (данные подставляет build.py)
│   └── configurator.html       собранный прототип — его и открывать
├── adapters/hyprpanel/
│   ├── options.json            окно настроек HyprPanel, вытащенное из исходников
│   ├── defaults.json           стандартные значения всех ключей
│   ├── strings.json            строки интерфейса для перевода
│   └── ru.json                 перевод
├── tools/
│   ├── hyprpanel_extract.py    исходники HyprPanel → options/defaults/strings
│   └── build.py                всё вместе → prototype/configurator.html
└── docs/research.md            где что хранится: HyprPanel, fastfetch, neofetch
```

## Пересборка

```bash
cd ~/mors-dots/configurator
python tools/build.py                                    # значения из репозитория + текущая тема
python tools/build.py --config ~/.config/hyprpanel/config.json   # твой живой config.json
```

После обновления HyprPanel:

```bash
git clone --depth 1 https://github.com/Jas-SinghFSU/HyprPanel /tmp/HyprPanel
python tools/hyprpanel_extract.py /tmp/HyprPanel
python tools/build.py        # перечислит строки, которых ещё нет в ru.json
```
